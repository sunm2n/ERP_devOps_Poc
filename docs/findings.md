# Findings

PoC 진행 중 나온 것들을 쌓는다. **보고서 5장(실패 항목과 원인)과 7장(다음 단계 권고)이
여기서 나온다.** 4단계에 2~3일밖에 없으므로 그때 기억으로 재구성하지 않는다.

## 무엇을 적는가

| 분류 | 내용 | 보고서 행선지 |
| --- | --- | --- |
| `가설판정` | H1~H8 의 참/거짓과 근거 | 3장 결과 요약표 |
| `실패` | 안 된 것과 그 원인 | 5장 |
| `설계영향` | 확정된 ADR / 여전히 미결인 ADR | 6장 구분표 |
| `도입권고` | PoC 에서 넘어갔지만 실도입에 필요한 것 | 7장 |
| `한계` | PoC 가 답하지 못한 것 | 2장·7장 |

**실패는 유효한 결과다.** 특히 H5(롤백)는 실패가 예상되고, "롤백 불가"라는 결론
자체가 가장 값어치 있는 산출물일 수 있다. 억지로 성공시킨 기록보다 정확한 실패 기록이 낫다.

## 가설 판정 현황

**상태는 4종만 쓴다: `미착수` / `참` / `거짓` / `판정불가`.**
"부분 성공", "조건부 참" 같은 걸 쓰면 보고서 3장 요약표가 그대로 받지 못한다.
`판정불가` 는 환경 미확보 등으로 검증 자체를 못 한 경우다 — `거짓` 과 다르다.

## 기록

새 항목은 아래에 덧붙인다. 형식:

```
### [분류] 한 줄 제목
**출처**: PR #N / 이슈 #N / 리뷰 관점
**ADR**: 관련 ADR 번호. 아직 모르면 빈칸으로 두되 필드는 남긴다
**내용**: 무엇이 관찰됐는가
**영향**: 어느 결정에 무엇을 의미하는가
**권고**: (도입권고 분류일 때 필수) ~할 것
```

`ADR` 필드는 비워두더라도 형식에 있어야 한다. 전제 문서가 3주차 전 반입이라 지금은 번호를
못 적지만, 필드가 없으면 4단계에 매핑 작업이 통째로 남는다.
**도입권고 분류는 권고 문장으로 끝나야 한다.** 문제 서술만 남으면 7장에 못 쓴다.

### [도입권고] 공개키·검증 스크립트의 대역 외 배포가 고객사 수에 정비례한다
**출처**: PR #2 보안·실무도입 리뷰
**내용**: 신뢰 앵커(GPG 공개키 + `verify-bundle.sh`)는 번들과 다른 경로로 먼저 도착해야 한다.
번들 안에 넣으면 변조자가 키와 검증 코드를 함께 바꿔치기할 수 있어 검출력이 체크섬과 같아진다.
PoC 는 VM-2 1대라 1회로 끝나 비용이 안 보인다.
**영향**: 고객사 100곳이면 초기 주입 100회, **키 회전 때마다 다시 100회**. 대역 외 주입은
정의상 원격으로 못 한다 — 물리 방문이거나 고객사 담당자 손이다. 7장 권고는 "어떤 키를 쓸까"가
아니라 **"회전 1회 비용 = 고객사 수 × 대역 외 전달"** 이라는 산식으로 써야 쓸모가 있다.

**권고**: 7장 권고를 "어떤 키를 쓸까"가 아니라 **"회전 1회 비용 = 고객사 수 × 대역 외 전달"**
이라는 산식으로 쓸 것. PoC 에서 VM-2 1대 주입 실측 시간(`metrics.md` 의 `(b) 중 앵커 주입분`)을
그 산식의 계수로 남긴다.

### [도입권고] 서명 키를 CI 러너에 두면 파이프라인 실행 권한이 곧 서명 권한이 된다
**출처**: PR #2 보안 리뷰
**내용**: PoC 는 CI 변수에 개인키를 넣고 서명한다. 1인 운영에서는 정당한 타협.
**영향**: 실도입 시 서명을 별도 승인 게이트가 붙은 잡으로 분리하거나 HSM/KMS, 최소한
protected+masked 변수 + protected 브랜치 한정으로 올려야 한다. `.gitignore` 와 CI 개인키
검사는 *커밋* 만 막고 *CI 변수* 는 못 막는다.
**권고**: 실도입 시 서명을 별도 승인 게이트가 붙은 잡으로 분리하거나 HSM/KMS, 최소한
protected+masked 변수 + protected 브랜치 한정으로 올릴 것. **폐쇄망에는 revocation 이
전파되지 않아 CRL 이 사실상 동작하지 않으므로** 키 유출 시 대응을 별도 설계 항목으로 잡는다.

### [도입권고] 폐쇄망 롤백은 고객사 디스크를 2배 요구한다
**출처**: PR #2 실무도입 리뷰
**내용**: 폐쇄망에는 `docker pull` 이 없어 롤백은 직전 버전 이미지가 이미 로컬에 있을 때만 성립한다.
**영향**: 롤백 가능성을 유지하려면 **모든 고객사가 항상 직전 버전 이미지를 상시 보관**해야 한다.
번들이 수백 MB 면 고객사당 상시 +수백 MB. "언제 구버전을 지워도 되는가" 정책이 없으면
3년 뒤 고객사 디스크가 이미지로 찬다.
**권고**: 고객사 최소 디스크 요구사항에 `이미지 점유량 × 보관 세대 수` 를 명시하고, 세대 정리
정책(N세대 초과 시 자동 삭제)을 설치 스크립트에 넣을 것. 계수는 tar 크기가 아니라 **`docker load`
후 로컬 이미지 점유량**이다 — 압축 해제와 레이어 때문에 tar 크기로 계산하면 과소 추정된다.
`metrics.md` 의 `로컬 이미지 점유량` 행이 그 값이다.

### [한계] H5 실패 시 대안인 "스냅샷 기반 복구"가 고객사 전제를 요구한다
**출처**: PR #2 실무도입 리뷰
**내용**: `plan.md` 는 H5 가 거짓일 때 대안으로 스냅샷 기반 복구를 제시한다. PoC 는 스냅샷
가능한 하이퍼바이저를 전제로 설계됐고 우리 랩에서는 확보하면 그만이다.
**영향**: 고객사 현장은 물리 서버이거나 스냅샷 권한이 고객사 인프라팀에 있는 경우가 흔하다.
**PoC 에서 성립한 대안이 현장에서는 성립하지 않을 수 있다.** H5 가 실패로 나올 확률이 높다고
계획이 스스로 말하므로, "롤백 정책 확정 전 고객사 인프라(스냅샷/백업 수단) 실태 조사"는
PoC 결과와 무관하게 필요하다.

### [한계] 버전 스큐를 한 경로만 검증한다
**출처**: PR #2 실무도입 리뷰
**내용**: H4 는 v1.0 → v1.3 하나만 본다.
**영향**: 실제로는 고객사가 여러 버전에 흩어져 있고 릴리스마다 조합이 늘어난다.
고객사 20곳이 서로 다른 버전에 있으면 묶음 번들은 고객사마다 내용물이 달라 **"번들 1종을
100곳에 복사"가 아니라 고객사별 조립**이 된다. H6 가 파이프라인을 만들어도 번들 조립은
그 바깥에 남는다. 범위를 늘리자는 게 아니라 **"검증한 경로는 1개였다"를 3장 요약표에 명시**하자는 것.

### [도입권고] 고객사가 지금 어느 버전인지 우리가 아는 방법이 없다
**출처**: PR #2 실무도입 리뷰
**내용**: 설치 스크립트의 적용 이력은 고객사 VM 안에만 append 된다. 폐쇄망이라 우리가 못 읽는다.
**영향**: 어떤 번들을 만들지 정하려면 고객사 담당자에게 물어야 한다 — 100곳이면 릴리스마다
100회 확인, 오답 1건당 잘못된 번들 USB 운반 후 현장 재방문. **H4 가 검증한 기술적 능력과
무관하게 운영이 막힌다.** 
**권고**: 적용 이력을 반출 가능한 1파일(서명된 상태 리포트)로 뽑는 명령을 설치 스크립트에
넣을 것. 아래 `기록 규율` 항목의 권고와 **같은 산출물로 묶는다**.

### [도입권고] 관측 장치는 PoC 에만 있고 고객사에는 안 들어간다
**출처**: PR #2 실무도입 리뷰
**내용**: `DOCKER-USER` LOG · dnsmasq 싱크홀 · tcpdump · journald 영속화는 H3 를 판정하려고
VM-2 에 거는 계측이지 고객사 운영 설비가 아니다.
**영향**: 빼면 고객사 현장에서 "이번 배포가 외부로 안 나갔다"를 보증할 수단이 없다.
숨은 외부 의존성이 새 버전에서 늘어나도 아무도 모른다. **PoC 는 통과하는데 운영에는 검증
수단이 없는 상태.**
**권고**: 운영용 경량 확인 스크립트(설치 전후 egress 시도 카운트 1개 출력) 1벌을
산출물에 추가할 것.

### [설계영향] 폐쇄망 검증에서 차단 계층과 관측 계층은 분리해야 한다
**출처**: PR #2 CI/CD·실무도입 리뷰 (관점 충돌에서 도출)
**내용**: CI/CD 는 `DOCKER-USER` 체인에서 차단+로깅을 제안했고 실무도입은 "차단은 VM 바깥,
iptables 는 관측 보조"를 요구했다. 두 제안은 배타적이지 않고 계층이 다르다.
**영향**: iptables 를 차단 수단으로 쓰면 "방화벽 규칙만 걸고 넘어가는" 상태가 되고 규칙이
스냅샷 복구에 살아남지 않는다. 반대로 가상 NIC 를 떼면 경로가 없어 forward 훅이 순회조차
하지 않아 iptables 로그만 0 이 되는 반쪽 계측이 된다. **차단은 격리 네트워크 + 블랙홀
게이트웨이, 관측은 `DOCKER-USER`+pcap+DNS 싱크홀.** PoC 의 초기 발견 중 하나다.

### [설계영향] 신뢰 앵커는 키와 코드 양쪽이다
**출처**: PR #2 보안 리뷰 라운드 2·3
**내용**: 공개키만 대역 외로 빼면 절반이다. 번들 안 `install.sh` 의 `gpg --verify` 호출을
삭제하면 사전 배치한 키는 아무도 읽지 않는다. 그리고 음성 대조 (a)(b)는 앵커 *키* 를
검증할 뿐 앵커 *코드* 를 검증하지 않는다 — 둘 다 `verify-bundle.sh` 를 먼저 돌리는
전제에서 수행되기 때문이다.
**영향**: 실제 통제 수단은 대조가 아니라 **`verify-bundle.sh` 선행 실행이라는 절차 그 자체**다.
7번 ⑧(c)가 그 사실을 기록으로 남긴다(설치가 성공하는 것이 기대 결과). 실도입 시에는
`verify-bundle.sh` 가 기대 지문을 하드코딩하고 불일치 시 중단해야 한다 — `gpg --verify`
성공 여부가 아니라 **서명자 지문 == 사전 등록 지문** 비교가 판정이어야 한다.

### [한계] 운반 시간은 PoC 에서 원리적으로 채워지지 않는다
**출처**: PR #31 실무도입 리뷰
**ADR**:
**내용**: 사내 랩에는 반입 승인도 보안 검사도 담당자 일정도 없다. 실측되는 것은 물리 복사 몇 분뿐이다.
그러면 "추측을 값으로 쓰지 않는다"는 규칙에 따라 이 칸은 `미측정` 이 되고,
**"운반 칸을 반드시 병기한다"는 원칙이 보고서에서 빈칸으로 병기된다.**
**영향**: 고객사 100곳이면 반입 정책도 100가지다 — USB 자체가 금지된 곳, 부서장 결재가 필요한 곳,
반입 담당이 고객사 보안팀인 곳.
**권고**: 7장에 "운반 X분"이 아니라 **"반입 리드타임은 PoC 로 측정 불가. 계약 전 고객사별 반입 절차
실태 조사가 선행 항목"** 으로 쓸 것. `metrics.md` 는 `PoC 실측` / `고객사 반입 절차(미측정)` 로 쪼개뒀다.

### [한계] 모든 값이 표본 1이고 측정자가 설계자 본인이다
**출처**: PR #31 실무도입 리뷰
**ADR**:
**내용**: VM-2 는 1대, 각 측정은 1회다. 특히 "사람 개입 시간"은 지표 중 **숙련도 편차가 가장 큰 값**인데
PoC 측정자는 번들 구조와 `verify-bundle.sh` 절차를 직접 설계한 사람이다.
**영향**: 고객사 담당자가 절차서를 처음 보고 수행하는 시간과는 배수로 다르다. 그 값에 고객사 100곳을
곱하면 **체계적으로 과소 추정된 총량**이 나오고 그게 인력 산정 근거가 된다.
**권고**: 보고서 4장에 모든 값의 **측정 횟수 = 1, 측정자 = 설계자**를 명시하고, 사람 개입 시간만은
실도입 전 **비설계자 1인 재측정**을 별도 항목으로 잡을 것.

### [설계영향] "PoC 계측 오버헤드 = 운영 비용 아님"은 절반만 맞다
**출처**: PR #31 실무도입 리뷰
**ADR**:
**내용**: 오버헤드 칸의 항목 중 **스냅샷 촬영·덤프 대조·증거 반출은 실도입에서도 형태를 바꿔
발생한다** — 업그레이드 전 백업, 마이그레이션 후 데이터 검증, 폐쇄망 장애 증거 반출은 고객사
현장에서도 누군가 한다. 시계 보정·양성/음성 대조만 순수 PoC 전용이다.
**영향**: 한 칸으로 두면 보고서 4장이 "운영 비용에서 뺀 시간"을 실제보다 크게 잡아
**실도입 운영 부담이 과소 계상**된다.

### [한계] 고객사 VM 의 OS 전제가 한 번도 검증되지 않는다

잡을 것 — 대역 외 주입 시점에 1회 돌려 gpg 유무·버전·로그 경로 쓰기 권한·필수 커맨드를
확인하고 1줄로 뱉는다. 첫 설치 전화 대부분이 여기서 사라진다. PoC 에서는 만들지 않는다

### [한계] 검증한 바이트와 설치되는 바이트를 묶는 것이 없다

**영향**: 절차를 지키는 운영자에게는 문제없고, 지키지 않는 경우는 (c)가 이미 관측한다.

다이제스트를 재대조하게 할 것. PoC 에서는 절차서에 다이제스트 육안 대조 1행으로 대체한다.

### [한계] 감사 로그의 무결성 자체가 보증되지 않는다

### [설계영향] 번들 신원의 단위와 체크섬·서명 파일 규약이 아직 계약이 아니다

**ADR**:
**내용**: 묶음 tar 1개에 버전 3개면 "번들 버전" 이라는 단일 값이 없다. 5장의 번들 크기

#19 가 이대로 만들어야 하는데 아직 문서상 계약이 아니다.
**영향**: 어긋나면 정상 번들이 exit 6/10 으로 떨어지고, 재운반은 그걸 고치지 못한다.
버전 단위가 모호하면 H4 측정 대상이 흔들린다.
**권고**: **#19 에서 묶음 매니페스트(무엇이 들어 있는가)와 버전별 매니페스트를 분리**하는
결정을 내리고, 체크섬·서명 파일 규약을 `deploy/README.md` 에 계약으로 명시할 것.

### [설계영향] 실도입에서 지문을 하드코딩하면 키 회전이 스크립트 재배포가 된다

**ADR**:
**내용**: 지금은 파일 경로 하나라 회전이 **파일 교체**로 끝난다. 기존 findings 의
"실도입 시 `verify-bundle.sh` 가 기대 지문을 하드코딩" 권고를 그대로 가면 회전 1회가

**영향**: 어느 쪽을 택하느냐가 회전 비용을 한 자릿수 바꾼다. 하드코딩은 지문 파일 변조를
막고, 파일 방식은 회전을 싸게 한다 — 상충한다.
**권고**: 6장 미결 ADR 후보로 올릴 것. 절충안(스크립트에 지문을 굽되 서명된 지문 파일을
허용)도 함께 검토한다.

### [설계영향] 종료 코드 표를 계약으로 쓰려면 "표 밖 코드" 규약이 필요하다
**출처**: PR #32 CI/CD·보안 리뷰 라운드 2
**ADR**:
**내용**: `verify-bundle.sh` 는 `errexit` 로 `die()` 를 건너뛴 `1` 과 SIGPIPE `141` 을 낼 수
있었다. 둘 다 README 종료 코드 표에 없고, `die()` 를 안 거치므로 원인·조치·로그 경로가
한 줄도 안 나온다. 임계값이 파이프 버퍼 크기에 의존해 **같은 번들이 macOS 에서 `0`,
Linux 에서 `141`** 이었다.
**영향**: 폐쇄망에서 표에 없는 코드는 담당자에게 "원인 불명" 과 같고, "재운반이 고치는 것은

### [설계영향] 매니페스트의 직렬화 형식이 감사 기록의 유무를 가른다

### [설계영향] 종료 코드 닫힌 집합은 "셸이 정상 종료할 때"만 성립한다
**출처**: PR #32 CI/CD 리뷰 라운드 3
**ADR**:
**내용**: `SIGHUP`(129)·`SIGTERM`(143)은 EXIT trap 을 건너뛴다. 수백 MB 해싱 구간이 있어
세션 끊김·타임아웃이 현실적인 종료 사유인데, 그때 표에 없는 코드가 나오고 원인·조치·로그
경로가 한 줄도 안 나왔다.
**영향**: 기존 `종료 코드 표를 계약으로 쓰려면 "표 밖 코드" 규약이 필요하다` 의 권고를
**선택이 아니라 계약의 일부로 승격**해야 한다. 그리고 `128+N` 대역을 `1`("공급사 문의")로
접으면 **자기가 Ctrl-C 한 검증 때문에 공급사 에스컬레이션이 열린다.**
**권고**: 신호를 `130`("중단됨, 재실행")으로 모으고 표에 행을 넣었다(이 PR). 규약에
**128+N 대역은 중단이며 재실행이 정답**임을 명시할 것.

### [설계영향] `.asc` 컨테이너 append 는 "봉인"이 아니라 "필터"로만 방어된다
**출처**: PR #32 보안·CI/CD 리뷰 라운드 3·4
**ADR**:
**내용**: `.asc` 는 서명되지 않은 컨테이너다. 운반 구간에서 서명 블록을 `cat` 으로 덧붙이는
것만으로 — **번들·체크섬은 손도 대지 않고** — 정품 번들을 죽일 수 있다. 같은 원시에서
세 번 나왔다: 라운드 2 첫 `VALIDSIG` 만 보던 exit 14, 라운드 3 전역 `REVKEYSIG` 의 exit 16,
라운드 4 전역 `NO_PUBKEY` 의 exit 12. 셋 다 "앵커 기준으로 좁히기" 로 막았다.
**영향**: **좁히는 규칙이 하나 빠질 때마다 DoS 가 되살아난다.** 그리고 다 막아도 공격자는
여전히 검증 로그에 낯선 서명자 지문을 남길 수 있어, 감사 로그를 읽는 사람에게는 매번
조사 트리거가 된다 — 그 조사는 폐쇄망 안에서만 가능하다. exit 12 의 조치문이 운영자를
**앵커 재배포 경로**(가장 비싼 지원 경로)로 보낸다는 점도 크다.
**권고**: 실도입에서 `.asc` 를 **서명자별 1파일 규약**(`bundle.tar.<keyid>.asc`)으로 고정하거나,
검증기가 **앵커 키 서명 블록만 추출해 검증**하도록 바꿀 것. 그러면 append 자체가 무의미해진다.
지금 구조는 append 를 막는 게 아니라 영향을 좁히는 것이고, 규칙 목록이 늘어날수록 빠뜨릴 자리도 늘어난다.

### [한계] 앵커 미배치 상태에서는 전역 판정 fallback 이 그대로 공격면이다

### [한계] 출력 상한의 "단위"가 세 번째 환경 종속 축이었다
**출처**: PR #32 CI/CD 리뷰 라운드 4
**ADR**:
**내용**: `awk` 의 `length()`/`substr()` 는 mawk·BSD awk·gawk(C 로케일)에서 **바이트**,
gawk(UTF-8 로케일)에서 **문자**다. 같은 한글 1줄이 2048B 로도 6144B 로도 잘렸다. 게다가
바이트 절단이 UTF-8 시퀀스를 중간에서 잘라 로그가 깨진 바이트로 끝나고, 엄격한 UTF-8
소비자(로그 수집기 등)가 그 줄에서 실패했다.
**영향**: 상한의 **범위**(합산 vs 파일별) → **축**(줄 vs 바이트) → **단위**(바이트 vs 문자).
같은 자리에서 축만 바꿔 세 번 나왔다. `tr` 에서 없앤 "OS 마다 다른 기록" 이 절단 경계로
자리를 옮긴 것이다.
**권고**: `LC_ALL=C` 고정 + UTF-8 경계 되감기로 고쳤다(이 PR). 실도입 요건의
"검증 산출물의 문자 인코딩과 로케일 전제" 에 **"상한은 바이트 단위이며 도구 로케일을
`LC_ALL=C` 로 고정한다"** 를 명시할 것. 절차서의 로케일 고정만으로는 부족하다 —
스크립트가 자기 파이프라인의 로케일을 직접 고정해야 `sudo`·cron·원격 실행에서 같아진다.

### [설계영향] 종료 코드는 로그에도 남아야 계약이다
**출처**: PR #32 CI/CD 리뷰 라운드 4
**ADR**:

이 핸들러가 존재하는 이유가 "세션 끊김" 인데, 세션이 끊기면 **화면이 바로 그 사라지는 매체**다.
담당자에게 남는 건 헤더 3줄에서 끊긴 로그뿐이고, 공급사는 hang 을 의심하게 된다.
**영향**: 기존 `종료 코드 표를 계약으로 쓰려면 "표 밖 코드" 규약이 필요하다` 는 *코드*를
계약으로 올렸지만 **그 코드에 대응하는 로그 항목이 규약에 없었다.** 폐쇄망에서 종료 코드는
담당자의 셸에서 즉시 휘발하고, 공급사에 도달하는 것은 로그 파일이다.
**권고**: 130 도 로그에 쓰도록 고쳤다(이 PR). `#19`·`#20` 완료 조건에
**"표의 모든 종료 코드는 로그에 자기 코드와 조치를 남긴다"** 를 넣을 것.

### [설계영향] 판정을 실어 나르는 셸 구조가 판정 로직과 별개의 공격면이다

"좁히기 규칙을 빠뜨림" 으로 규정했는데, **이번 4번째 재발은 규칙이 아니라 셸 역학 때문**이다.
규칙을 아무리 정확히 써도 그 위에서 통째로 무력화된다. 재발 축이 하나 더 있는 것이다.
**권고**: 판정 경로의 파이프를 전부 셸 내장 패턴 매칭으로 교체했다(이 PR). 실도입 코딩 규약에
**"판정 분기는 서브프로세스·파이프 없이 셸 내장으로만 구현한다"** 를 추가하고, 위 `.asc`
서명자별 1파일 규약과 함께 올릴 것. **CI 를 한 플랫폼만 돌리면 못 잡는다**는 점도 명시한다.
