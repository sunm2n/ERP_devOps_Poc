# 지표 기록표

`plan.md` 5장. **측정한 자리에서 채운다.** 미측정은 `미측정` 과 이유를 적는다.

`근거` 칸에는 값을 뽑은 명령이나 파일을 적는다 — 예: `raw/window-a-count.txt / 2026-09-03 김OO(절차 설계자)`. 파일명은 계수 창 대장의 `pcap 파일(들)` 칼럼을 정본으로 삼는다.

> **추적 파일에는 식별자를 쓰지 않는다.** 주소·호스트명·FQDN 은 `<내부IP-A>`, `<레지스트리-A>`
> 같은 자리표시자로 적고, 실값 대응표는 `raw/` 에만 둔다. 이 저장소는 PUBLIC 이고,
> 폐쇄망 구성 자체가 정찰 정보다. `.gitignore` 도 CI 도 이건 못 막는다.

> **축소안 1번(VM-1 + H7 폐기)을 택하면** `패치 1건 개입 시간 (온라인)` 과 H7 관련 값은
> 영구 미측정이다. 빈칸으로 두지 말고 `미측정 — 축소 1번으로 VM-1 미구축` 으로 확정해 적는다.
> 그러면 보고서는 폐쇄망 값만 들고 "온라인 대비" 비교축을 잃는다는 사실도 함께 기록된다.
>
> **축소안 2번(마이그레이션 4→3단계)을 택하면** 아래 `v1.0/v1.2/v1.3` 을 `v1.0/v1.1/v1.2` 로,
> 스냅샷은 `v1.1-installed`/`v1.2-upgraded` 로 한 칸씩 내려 읽는다.

### 계수 창 대장 — 창 1개당 1행

`plan.md` 7번 ① 이 "시작시각을 기록한다. **사후에 기억으로 채우면 안 된다**"고 못박은 값이 여기 들어간다.
아래 판정 명령의 `--since`/`--until` 이 이 표에서 나온다.

| 창 | 무엇을 재는가 | 시작시각 | 종료시각 | pcap 파일(들) | IPv4 계수 | IPv6 계수 | DNS 계수 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | **OS 노이즈 baseline** (0단계, 번들 미설치) | | | | | | |
| A | **H3 판정** (7번 ①~③) | | | | | | |
| B | 멱등 2회차 (7번 ⑥) | | | | H3 계수 대상 아님 | H3 계수 대상 아님 | H3 계수 대상 아님 |
| C | 음성 대조 3종 (7번 ⑧) | | | | H3 계수 대상 아님 | H3 계수 대상 아님 | H3 계수 대상 아님 |

**H3 값 = 창 A 계수 − 창 0 계수(baseline).** 초과분을 계산한 흔적이 이 표에 남아야, 4단계에서
H3 `값` 이 원계수인지 초과분인지 구분된다. B·C 의 egress 가 섞이면 H3 이 비-0 이 된다.

pcap 회전과 파일 수 확인은 아래 `판정 명령` 절의 준비 사항 표를 따른다.

### 판정 명령

**명령의 정본은 [`plan.md` 3장](../plan.md) 하나다. 여기에 복제하지 않는다.**

복제해 두었더니 두 번 사고가 났다 — IPv6 블록의 `awk` 축약이 한쪽에만 고쳐졌고,
DNS 명령이 정본 쪽에만 낡은 채 남았다. 둘 다 실행하면 `0` 이 찍히는 형태였고
목표치도 `0` 이라 아무도 다시 안 봤을 것이다. 그래서 사본을 없앤다.

정본에서 가져와 쓸 때 필요한 준비만 여기 적는다.

| 무엇 | 준비 |
| --- | --- |
| `--since` / `--until` | 위 계수 창 대장의 시작·종료시각 |
| DNS 로그 | 창 열 때 `truncate -s 0 /var/log/dnsmasq.log`, 닫을 때 `cp` 로 `raw/<창>-dns.log` |
| pcap | `-w raw/<창>.pcap` 로 띄운다. 회전되면 `raw/<창>.pcap0`, `.pcap1` … 이 되고 판정은 glob 로 반복한다 |
| pcap 파일 수 | 창을 닫을 때 **10 미만인지 확인해 대장에 적는다.** `-W 10` 은 상한이 아니라 링버퍼라 10이면 초반 증거가 지워졌다 |

**판정값 `0` 은 항상 "앞단이 죽어서 0" 을 먼저 배제하고 기록한다.**
`wc -l` 은 앞단이 죽어도 `0` 을 찍고, `set -o pipefail` 로도 부족하다 —
프로세스 치환(`<(...)`)의 실패는 파이프라인 종료 상태에 들어가지 않는다(실증: exit 0, 출력 0).
중간 산출물의 줄 수를 눈으로 확인한 뒤 계수하라.

> 시도가 1건이라도 있으면 무엇인지 규명한다. NuGet, 이미지 pull, 라이선스 확인,
> 시간 동기화, **OCSP/CRL** 이 흔하다. 규명 결과를 적을 때 실주소를 쓰지 말고 자리표시자를 쓴다.

- **촬영/복구**: `촬영` 또는 `복구`
- **소요**: 촬영/복구 자체에 걸린 시간. **오버헤드 행의 값은 이 칼럼과 `이미지 재로드 소요` 의 합으로 정의한다** — 러닝 탤리를 머릿속에 두면 4단계에 안 남는다
- **공개키 지문**: `gpg --fingerprint`. 복구가 대역 외 주입분을 되돌렸는지 확인한다. 이게 없으면 7번 ⑧ 음성 대조가 "앵커가 없어서" 실패하는지 "서명이 깨져서" 실패하는지 구분되지 않는다
- **계측 생존**: `iptables -L DOCKER-USER -n -v` 규칙 잔존 + `systemctl is-active dnsmasq`
- 하이퍼바이저가 live snapshot(메모리 포함)인지 디스크 온리인지를 첫 행 근거에 적는다 — 복구 후 컨테이너 상태가 달라진다

> 복구는 시계도 되돌린다. NTP 가 막혀 있어 과거 시각이 유지되고, GPG·TLS 검증이
> 시계 오차로 실패하면 번들 문제로 오인하기 쉽다.
